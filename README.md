# Herdr 이슈 대시보드

`herdrdev/herdr`의 공개 GitHub 이슈와 릴리스를 조회하는 대시보드입니다. React 화면에서 이슈를 검색하고 상태·라벨로 좁혀 보며, 라벨별 이슈 수와 릴리스 변경 내용을 확인할 수 있습니다. Node.js API 서버가 데이터 조회, 필터링, 집계를 처리합니다.

기본 데이터는 저장소에 포함된 스냅숏입니다. 화면 아래에서 실시간 GitHub 조회로 전환할 수 있습니다. 이슈 생성·수정 기능은 없으며, 제목을 누르면 GitHub 원문이 새 탭으로 열립니다.

## 요구사항 및 설치

- Node.js **22.12.0 이상**과 npm
- 웹 브라우저
- 의존성 설치 및 실시간 조회 시 인터넷 연결

저장소 루트에서 의존성을 설치합니다.

```sh
npm ci
```

별도의 GitHub 토큰 설정은 필요하지 않습니다. 기본 스냅숏 조회는 설치 후 GitHub 연결 없이 사용할 수 있습니다.

## 실행

```sh
npm run dev
```

[http://127.0.0.1:5173](http://127.0.0.1:5173)에 접속합니다. 이 명령은 API 서버와 Vite 개발 서버를 함께 시작합니다. 종료할 때는 터미널에서 `Ctrl+C`를 누릅니다.

- 화면: `127.0.0.1:5173`. 해당 포트가 사용 중이면 개발 서버가 시작되지 않습니다.
- API: 기본 포트 `4174`. 화면의 `/api` 요청은 개발 서버가 API 서버로 전달합니다.
- API 포트 변경: `API_PORT` → `PORT` → `4174` 순서로 적용하며, 개발 스크립트가 API 서버와 프록시의 포트를 맞춥니다.

다음은 macOS/Linux 셸에서 API 포트를 바꾸는 예입니다.

```sh
API_PORT=4175 npm run dev
```

## 화면 사용법

### 이슈 검색과 필터

상단의 **이슈** 탭에서 목록을 확인합니다.

| 기능 | 사용법 및 동작 |
| --- | --- |
| 검색 | `제목 또는 #번호 검색`에 제목 일부나 번호를 입력합니다. 예: `kitty`, `#5441`. 앞뒤 공백과 맨 앞의 `#` 하나를 제거한 뒤 대소문자 구분 없이 제목 또는 번호에 부분 일치하는 이슈를 찾습니다. |
| 검색 하이라이트 | 제목에서 검색어와 일치하는 부분을 강조합니다. 반복해서 등장하는 부분도 강조하며, 특수문자는 일반 문자로 검색합니다. 번호 표시 자체는 강조하지 않습니다. |
| 상태 | `모든 상태`, `열림`, `닫힘` 중 선택합니다. |
| 라벨 | `모든 라벨`, 개별 라벨, `라벨 없음` 중 선택합니다. 라벨 목록은 선택된 데이터 전체를 기준으로 제공됩니다. |
| 초기화 | 검색어·상태·라벨을 기본값으로 되돌립니다. 데이터 소스 선택은 유지됩니다. |

검색은 입력이 멈춘 뒤 약 250ms 후 반영되고, 상태·라벨 변경은 바로 요청됩니다. 세 조건은 모두 만족해야 합니다. 예를 들어 `windows` 검색, `열림` 상태, `sessions` 라벨을 함께 선택하면 세 조건을 만족하는 이슈만 표시합니다.

목록 위에는 **전체 N개 중 M개**가 표시됩니다. 각 이슈에는 열림/닫힘 상태, 제목, 번호, 작성일, 라벨이 나오며 댓글이 있을 때 댓글 수도 표시됩니다. 제목을 누르면 해당 GitHub 이슈가 새 탭으로 열립니다. 결과가 없으면 **조건 초기화**로 필터를 해제할 수 있습니다.

### 라벨별 차트

**라벨별 이슈**는 선택된 데이터 전체에서 이슈 수가 많은 라벨을 최대 10개까지 막대와 건수로 보여 줍니다. 건수 내림차순이며 동률이면 라벨 이름순입니다.

검색이나 필터를 바꿔도 차트와 전체 건수는 줄어들지 않습니다. 한 이슈에 라벨이 여러 개 있으면 각 라벨에 포함되므로 라벨별 건수의 합이 전체 이슈 수보다 클 수 있습니다. 라벨이 없는 이슈는 `라벨 없음`으로 집계됩니다.

### 릴리스

상단의 **릴리스** 탭에서 릴리스 이름(없으면 태그), 게시일, 본문 요약을 확인합니다. 본문에서 빈 줄과 제목 줄을 제외하고 일부 Markdown 표기를 제거한 앞부분 최대 4줄을 표시하며, 남은 줄은 `외 N개 항목`으로 안내합니다. 릴리스 제목이나 **전체 변경 내용 보기**를 누르면 GitHub 릴리스가 새 탭으로 열립니다. 이슈 검색·필터는 릴리스 목록에 적용되지 않습니다.

### 데이터 소스와 오류 안내

화면 아래 **데이터** 선택에서 소스를 바꿉니다. 기준 시각, 출처, 데이터 범위도 함께 확인할 수 있습니다.

- **스냅숏**: 로컬 JSON 파일을 읽습니다. 기본 선택입니다.
- **실시간**: 스냅숏의 `repository`에 지정된 저장소에서 GitHub 이슈/PR 응답 최대 30개를 가져와 PR을 제외하고, 릴리스는 최대 3개를 조회합니다. 자동 주기 갱신은 없으며 소스나 검색·필터가 바뀔 때 요청합니다.
- 실시간 요청이 실패하거나 5초 제한을 넘으면 저장된 스냅숏으로 대체합니다. 상단 경고와 하단의 `스냅숏(실시간 실패로 대체)` 출처 표시를 확인하세요.
- API 연결 또는 데이터 읽기 오류가 발생하면 오류 메시지와 **다시 시도** 버튼이 표시됩니다. 검색·필터 요청 중에는 로딩 표시가 나타나며, 이전 이슈 목록이 남아 있으면 흐리게 표시됩니다.

**전체 건수와 차트는 현재 불러온 범위의 통계입니다. GitHub 저장소 전체 이슈 통계가 아닙니다.**

## 빌드

```sh
npm run build
```

Vite가 프런트엔드 배포 파일을 `dist/`에 생성합니다. API 서버는 빌드 결과에 포함되지 않습니다. 배포 시에는 정적 파일 제공과 `/api` 요청을 API 서버로 연결하는 구성이 별도로 필요합니다. API 서버만 실행하려면 다음 명령을 사용합니다.

```sh
node server/index.mjs
```

API 단독 실행의 기본 포트는 `4174`이며 `PORT`로 변경합니다. 이 서버는 `GET /api/dashboard`를 제공하며 `dist/` 파일을 제공하지 않습니다.

## 테스트

저장소 루트에서 실행합니다. 개발 서버를 미리 켤 필요는 없습니다. 테스트가 필요한 로컬 API 서버를 직접 시작하고 종료합니다.

```sh
npm test
npm run accept
```

- `npm test`: `tests/*.test.mjs`를 실행합니다. API 필터·집계·오류 응답·실시간 실패 시 대체 동작과 검색 하이라이트를 검증합니다. 실시간 응답은 테스트에서 대체하므로 GitHub 연결이 필요하지 않습니다.
- `npm run accept`: `acceptance/*.test.mjs`를 실행합니다. 실제 스냅숏을 기준으로 API의 집계, 필터 조합, 빈 결과, 잘못된 상태 값 처리 등 계약을 검증합니다.

## 데이터 위치

| 경로 | 용도 |
| --- | --- |
| [`data/snapshot.json`](data/snapshot.json) | 기본 실행 데이터. `repository`, `capturedAt`, `source`, `scope`, `issues`, `releases`를 포함합니다. 현재 파일은 2026-10-20 기준 이슈 26개와 릴리스 3개를 담고 있습니다. |
| [`contract/API.md`](contract/API.md) | `/api/dashboard`의 요청 매개변수, 응답 필드, 필터 및 집계 규칙입니다. |
| [`contract/fixture-default.json`](contract/fixture-default.json) | UI 단독 개발용 고정 응답 예시입니다. 실제 실행 시 데이터는 `data/snapshot.json`에서 읽습니다. |

다른 스냅숏을 사용하려면 같은 구조의 JSON 파일 경로를 `SNAPSHOT_PATH`에 지정합니다. 아래는 macOS/Linux 셸 예시입니다.

```sh
SNAPSHOT_PATH=/absolute/path/to/snapshot.json npm run dev
```

실시간 모드에서도 저장소 정보와 실패 시 대체 데이터를 위해 스냅숏 파일을 먼저 읽습니다. 실시간으로 조회한 결과는 스냅숏 파일에 자동 저장되지 않습니다. 기본 스냅숏의 건수와 내용을 전제로 하는 테스트가 있으므로 테스트 검증에는 저장소에 포함된 원본 데이터를 사용하세요.
